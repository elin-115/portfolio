Project 03 · Computer Vision · 해커톤 (개인) · 4위

흉부 X-ray 폐렴 분류 — 모델은 무엇을 보고 있었나

검증 정확도는 98.75%인데 리더보드는 0.90.
이 간극의 원인을 찾는 데 대부분의 시간을 썼습니다.

  • 폐를 전혀 보지 않고 사진의 가로세로 비율만으로 AUC 0.88이 나온다는 것을 찾았습니다.
    모델은 "검은 여백이 두꺼우면 폐렴"을 배우고 있었습니다
  • 여백을 잘라내는 전처리 후, 단서와 정답이 어긋나는 사진에서 정확도가 0.905 → 0.962로 올랐습니다
  • 모델 넷을 섞어 0.9215였던 점수가 여백을 지운 모델 하나로 0.9471, 같은 전처리 모델 셋 평균으로 0.9583이 됐습니다
  • 앙상블은 모델 수가 아니라 예측 간 상관으로 판단해야 한다는 것을 실패한 시도(v6)로 확인했습니다

2026.09 – 2026.10
Stack

Project 04 · Machine Learning · 팀 (5인)

재난현장 다수사상자 중증도 분류

사상자가 한꺼번에 나온 현장에서 누구를 먼저 후송할지 가리는 문제.
데이터 분석과 후송 시간 분석을 맡았습니다.

  • 넣으면 정확도는 오르지만 현장에서는 알 수 없는, 정답이 새어 든 칸 17개를 먼저 걷어냈습니다
  • 대본 15종을 돌려 쓰는 가상 데이터라 분할 단위 4가지를 직접 비교해 템플릿 단위 교차검증을 택했습니다
  • 정확도가 아니라 과소분류율을 1순위 지표로 두고, START 규칙과 XGBoost 중 더 위급한 쪽을 택하게 했습니다
  • 가장 위급한 적색이 가장 늦게 출발한 원인이 인력이 아니라 출발 순서 규칙임을 시간 분석으로 밝혔습니다
Result
과소분류 6.3% → 2.0%, 적색(최위급) 재현율 100%
Period
2026.09 – 2026.10

Project 05 · Tabular ML · 해커톤 (개인) · 2위

난임 환자 임신 성공 예측

시술 기록 25만 건으로 임신 성공 여부를 예측했습니다.

  • 같은 빈칸이 "해당 없음"과 "미기록" 두 뜻으로 들어온다는 것을 시술 유형(IVF / DI)별 결측률로 확인하고 갈라서 처리했습니다
  • 8개 컬럼의 최댓값이 똑같이 51.0인 것을 보고 상한 캡핑을 찾아냈습니다
  • 튜닝 효과는 +0.0004.
    성능을 가른 것은 모델 설정이 아니라 결측의 해석이었습니다
Result
5-fold AUC 0.740 · 해커톤 2위
Period

Stack
