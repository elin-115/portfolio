## Projects

### 1. 재난현장 다수사상자 중증도 분류 — [`projects/triage-soms`](projects/triage-soms)

사상자가 한꺼번에 발생한 현장에서 누구를 먼저 후송할지 가리는 문제. 

팀 프로젝트에서 데이터 분석과 후송 시간 분석을 맡았다.

- **정답이 새어 든 칸 17개를 먼저 걷어냈다.** 넣으면 정확도는 오르지만 현장에서는 쓸 수 없는 모델이 된다
- 대본 15종을 돌려 쓰는 가상 데이터라 **분할 단위 4가지를 직접 재서** 템플릿 단위 교차검증을 택했다
- 정확도가 아니라 **과소분류율**을 1순위 지표로 삼고, START 규칙과 XGBoost 중 더 위급한 쪽을 택하게 했다


| 방식             | 정확도    | 과소분류      | 과대분류   | 적색 재현율   |
| -------------- | ------ | --------- | ------ | -------- |
| START 규칙 단독    | 70.90% | 6.32%     | 22.79% | 100%     |
| XGBoost 단독     | 88.44% | 6.13%     | 5.43%  | 89.2%    |
| **규칙 + 모델 결합** | 73.45% | **2.04%** | 24.51% | **100%** |


후송 지연도 따로 진단했다. 등급은 4분이면 나오는데 가장 위급한 적색이 가장 늦게 출발했고(18.5분),
원인은 인력이 아니라 **출발 순서가 "처치가 언제 끝났는가"로 정해지는 것**이었다.

`Python` `pandas` `scikit-learn` `XGBoost`



### 2. 흉부 X-ray 폐렴 분류 — [`projects/xray-pneumonia`](projects/xray-pneumonia)

정상 / 폐렴 이진 분류 해커톤. baseline에서 v11까지 바꿔 나간 과정을 실패한 시도까지 남겼다.

- 검증 정확도 98.75%인데 리더보드는 0.90 — 이 간극의 원인을 찾는 것이 대부분이었다
- **폐를 보지 않고 사진의 가로세로 비율만으로 AUC 0.88이 나온다는 것**을 찾았다. 모델은 "검은 띠가 두꺼우면 폐렴"을 배우고 있었다
- 띠를 제거하자 단서와 정답이 어긋나는 사진의 정확도가 0.905 → 0.962로 올랐다
- 모델 넷을 섞어 0.9215였던 점수가, 띠를 제거한 **모델 하나로 0.9471**이 됐다
- 앙상블은 모델 수가 아니라 **예측 간 상관**으로 판단해야 한다는 것을 실패 사례(v6)로 확인했다

`PyTorch` `torchvision` `TorchXRayVision` `EfficientNet` `DenseNet` `ConvNeXt`



### 3. 난임 환자 임신 성공 예측 — [`projects/infertility-pregnancy`](projects/infertility-pregnancy)

시술 기록 25만 건으로 임신 성공 여부를 예측한 해커톤. 2위.

- 같은 빈칸이 "해당 없음"과 "미기록" 두 가지 뜻으로 들어온다. 시술 유형(IVF / DI)별로 결측률을 다시 재서 갈랐다
- 8개 컬럼의 최댓값이 똑같이 51.0인 것을 보고 상한 캡핑을 찾았다
- 튜닝의 효과는 +0.0004였다. 성능을 가른 것은 모델 설정이 아니라 결측의 해석이었다

`pandas` `XGBoost` `Optuna`



### 4. DUR 금기 의약품 분석 — [`projects/dur-ddi`](projects/dur-ddi)

식약처 DUR 병용·임부·연령 금기 데이터 분석.

- 정의서에 설명이 없던 `제품수`가 **성분 조합별 행 수**임을 groupby 최댓값(11,252)으로 확인하고 성분 단위로 재구성했다
- p = 4.8e-38인데 중앙값은 양쪽이 같았다 — 일괄 고시일에 몰려 생긴 착시였다
- 금기 사유 문장으로 등급을 분류하면 0.958, 정형 변수만 쓰면 0.567. 판별력은 텍스트에서 나왔다

`pandas` `scikit-learn` `gensim` `Keras` `konlpy`



### 5. 기술보증 대출 승인 예측 — [`projects/tech-credit`](projects/tech-credit)

결론이 "예측 모델을 만들었다"가 아니라 **"이 데이터로는 예측할 수 없다"** 였던 프로젝트.

- "대출금액이 0이면 거부"라는 규칙 하나가 정확도 97.97%였다. 대출금액은 심사의 입력이 아니라 결과다
- 빼고 다시 돌리니 AUC 0.47. 업력·기술등급·기술명 텍스트도 전부 승인과 무관했다

`pandas` `scikit-learn` `Keras` `konlpy`
