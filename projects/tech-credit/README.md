# 헬스케어 기술보증 대출 승인 예측

기술보증 심사 데이터로 **대출 승인 여부를 예측**하려 했다.
결론은 "예측 모델을 만들었다"가 아니라 **"이 데이터로는 예측할 수 없다"** 였고, 그걸 밝히는 과정이 이 프로젝트의 내용이다.

## 데이터

기업 정보(설립일·자본금·업력·기술등급), 기술명 텍스트, 대출금액, 승인 여부.

## 결론 — 대출금액이 정답이었다

처음 모델은 정확도가 아주 높게 나왔다. 그런데 변수를 하나씩 들여다보니 이유가 단순했다.

```
대출금액 == 0  →  거부   (405건 중 404건)
```

**"대출금액이 0이면 거부"라는 규칙 하나의 정확도가 97.97%다.**
대출금액은 심사 *결과*로 정해지는 값이지 심사 *입력*이 아니다. 전형적인 데이터 누수다.

빼고 다시 돌렸더니 **AUC 0.47** — 동전 던지기보다 못하다.

### 나머지 변수도 전부 무관했다

| 변수 | 검정 | 결과 |
|---|---|---|
| 업력 | t-검정 | p = 0.84 |
| 기술등급 | 카이제곱 | p = 0.19 |
| 기술명 (텍스트) | NN 교차검증 | AUC 0.50 |

즉 **주어진 변수로는 승인 여부를 설명할 수 없다.** 심사에 실제로 쓰인 정보가 이 데이터에 들어 있지 않다는 뜻이다.

### 부수적으로 찾은 것

- `총합 = 대출금액 + 자본금` — 파생 관계라 둘을 같이 넣으면 중복
- 설립일 `1900-01-01` 20건은 결측 표기
- 병원·의료 IT 분야에서 '감염'은 9회뿐이고 전부 "감염관리 모니터링 시스템" 한 템플릿

## 구조

```
src/
├── build_notebook.py        노트북 생성
└── build_notebook_심화.py    심화 버전 생성

notebooks/
├── mission4_tech_credit.ipynb        본편 — 수업에서 배운 도구 범위로 작성
└── mission4_tech_credit_심화.ipynb   Pipeline · 교차검증 루프를 쓴 버전
```

본편은 for문 / `value_counts` / `get_dummies` / `train_test_split` 수준으로 유지하고,
`Pipeline`·`ColumnTransformer` 같은 도구는 심화 노트북으로 분리했다.

학습된 모델(`model_loan.h5`)은 포함하지 않았다.

### 사용 도구

konlpy(Okt), CountVectorizer / TfidfVectorizer, gensim Word2Vec(Skip-Gram · CBOW),
Keras Tokenizer + pad_sequences, scikit-learn.
