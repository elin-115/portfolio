# 흉부 X-ray 폐렴 분류

흉부 X-ray 사진으로 **정상 / 폐렴**을 가리는 해커톤. 평가 지표는 Accuracy.
주최측 baseline(SimpleCNN, 2에포크)의 구조를 유지하면서 열한 번에 걸쳐 바꿔 나갔고, 실패한 시도까지 전부 남겼다.

OZ코딩스쿨 AI 헬스케어 7기 해커톤 · 2026.09.22 ~ 2026.10.18 (**진행 중**)

---

## 데이터

| | 장수 | 특징 |
|---|---|---|
| train | 5,216 | 정상 1,341 / 폐렴 3,875 — 전부 224×224 **letterbox**(비율 유지 + 검은 여백), 일부 회전·확대 증강됨 |
| test | 624 | **원본 크기** (1936×1554, 904×552 … 제각각) |

> 해커톤에서 제공받은 데이터라 저장소에 포함하지 않았다.

**가장 중요한 발견은 train과 test의 전처리가 다르다는 것이었다.**
train이 letterbox인데 test를 그냥 `Resize`하면 가로세로가 찌그러져 학습 때와 다른 그림이 된다.
test에도 같은 letterbox를 적용하는 것이 첫 번째 개선점이었다.

## 개선 과정

| 버전 | 모델 | 바꾼 것 | 리더보드 |
|---|---|---|---|
| baseline | SimpleCNN | 주최측 제공 (128px 흑백, 2 epoch) | — |
| **v1** | EfficientNet-B0 | letterbox 통일, 클래스 가중치, 10 epoch, 전이학습 | 0.9006 |
| v2 | EfficientNet-B0 | 환자 묶음 검증, label smoothing으로 과신 완화 | 0.8686 |
| v3 | DenseNet121 | 앙상블용 다른 계열 추가 | — |
| **v4** | EfficientNet-B0 ×5 | v1 설정으로 환자 묶음 5-fold, test 확률 평균 | 0.9022 |
| **v5** | TorchXRayVision DenseNet ×5 | ImageNet이 아닌 **흉부 X-ray 사전학습** 모델로 교체 | — |
| v4+v5 | 순위 평균 | 두 모델의 관점이 달라서(순위 상관 0.87) 섞음 | 0.9119 |
| v6 | X-ray 모델 3종 추가 | 사전학습 데이터가 다른 X-ray 모델을 더 넣음 → v5와 너무 비슷해(0.92~0.95) **효과 없음** | 0.8990 |
| v7 | ConvNeXt-Tiny ×5 | 다시 관점이 다른 모델을 찾아 앙상블 | 0.9119 (동점) |
| **v8** | EfficientNet-B0 ×5 + 폐 crop | 폐 분할 모델(PSPNet)로 폐 영역만 잘라 학습 | 0.9199 (v4+v5+v8) |
| **v9** | X-ray DenseNet ×5 + 폐 crop | X-ray 사전학습 모델에도 폐 crop 적용 | 0.9215 (v4+v5+v8+v9) |
| **v10** | EfficientNet-B0 ×5 | **검은 띠 제거** — 아래 참고 | 0.9183 (v10+v5+v8+v9) |
| **v11** | EfficientNet-B0 ×5 | v10에서 에포크만 6 → 10 | **0.9471 (단일 모델, 기준 0.5, 최고)** |

검증 정확도는 v1 단일 모델에서 이미 **98.75%**였다(혼동행렬 `[[263 5] [8 768]]`).
그런데도 리더보드는 0.90 언저리에 머물렀다. 그 간극의 원인을 찾는 것이 이 프로젝트의 대부분이었다.

### 모델은 폐가 아니라 검은 띠를 보고 있었다 (v10)

v9까지는 원인을 "train/test 분포 차이"라고만 적어 두고 앙상블로 버텼다. 전처리를 다시 점검하다가 이유를 찾았다.

| | 내용 영역 가로÷세로 (중앙값) | letterbox 후 모습 |
|---|---|---|
| 정상 | 1.18 | 위아래 검은 띠가 얇음 |
| 폐렴 | 1.44 | 위아래 검은 띠가 두꺼움 |

- 폐를 전혀 보지 않고 **가로세로 비율만으로 AUC 0.88**이 나온다. train에서 비율 1.5 이상은 99% 이상이 폐렴이다
- 그런데 test는 624장 중 263장(42%)이 비율 1.5 이상이다. **test에는 가로로 긴 정상 사진이 많은데 train에는 거의 없다**
- 모델은 "띠가 두꺼우면 폐렴"을 배웠고, 그동안의 오답(정상 → 폐렴 과신)과 정확히 맞아떨어진다
- v8·v9의 폐 crop이 효과 있었던 것도 띠가 같이 잘려 나갔기 때문으로 보인다

v10은 검은 띠를 잘라내고 내용만 224×224로 채운 뒤, 가로세로 비율 증강을 넣었다. test를 쓰지 않고 train의 교차검증만으로 확인했다.

| | 전체 | 가로로 긴 정상 (105장) | 정사각에 가까운 폐렴 (393장) |
|---|---|---|---|
| v4 (기존 전처리) | 0.9862 | 0.9048 | 0.9593 |
| v10 (띠 제거) | 0.9528 | **0.9619** | 0.8830 |

전체 검증 정확도는 내려갔지만 **단서와 정답이 어긋나는 사진**에서는 올라갔다.
test의 폐렴 판정 비율도 0.766 → 0.631로, 기준을 손대지 않고도 자연스러운 수준이 됐다.

대신 정사각에 가까운 폐렴을 더 놓쳤다(OOF 혼동행렬 `[[1321 20] [226 3649]]`). 과소적합으로 보고 v11에서 에포크만 6 → 10으로 늘렸다.

| | OOF 정확도 | 정상 → 폐렴 | 폐렴 → 정상 | 리더보드 |
|---|---|---|---|---|
| v10 (6 에포크) | 0.9528 | 20장 | 226장 | — (단독 미제출) |
| v11 (10 에포크) | 0.9601 | 17장 | 191장 | **0.9471** |

**v11은 모델 하나, 기준 0.5, 보정 없이 0.9471이다.** 이전 최고는 모델 넷을 섞고 판정 비율까지 맞춘 0.9215였다.

v10을 기존 모델들과 섞은 앙상블(v10+v5+v8+v9)은 0.9183으로 오히려 낮았다.
띠 단서를 배운 모델들이 섞이면 그 단서가 다시 들어오기 때문으로 보인다 — 앙상블이 답이 아니라 전처리가 답이었다.

### 앙상블에서 배운 것

v6이 실패한 이유가 쓸모 있었다. 앙상블은 모델을 **많이** 넣는다고 좋아지지 않는다.
v4(ImageNet)와 v5(X-ray 전용)는 순위 상관이 0.87이라 섞여서 올랐지만,
v5에 비슷한 X-ray 모델을 더 넣자 상관이 0.92~0.95로 올라가 오히려 점수가 내려갔다.
**섞을 가치가 있는지는 모델의 성능이 아니라 예측 간 상관으로 판단해야 한다.**

모델마다 확률의 눈금이 달라서(v1은 0.99 이상이 388장, label smoothing을 쓴 v3은 0장) 확률 평균 대신 **순위 평균**을 썼다.

## 구조

```
src/
├── xray_improved.py         v1 — baseline 개선
├── xray_v2.py               v2 — 환자 묶음 검증 + label smoothing
├── xray_v3_densenet.py      v3 — DenseNet121
├── xray_v4_kfold.py         v4 — 환자 묶음 5-fold 앙상블
├── xray_v5_xrv.py           v5 — TorchXRayVision 전이학습
├── xray_v6_xrv_multi.py     v6 — X-ray 모델 다중 앙상블 (실패 사례)
├── xray_v7_convnext.py      v7 — ConvNeXt-Tiny
├── xray_v8_lungcrop.py      v8 — 폐 분할 → 폐 영역 crop
├── xray_v9_xrv_lungcrop.py  v9 — X-ray 사전학습 모델 × 폐 crop
├── xray_v10_nobars.py       v10 — 검은 띠 제거
├── xray_v11_epochs.py       v11 — v10 + 에포크 10 (make_v11.py 로 생성)
├── xray_ensemble.py         학습된 .pt 를 불러와 앙상블
└── build_nb.py              .py (# %% 셀) → .ipynb 변환, 코랩용 주석 자동 해제

notebooks/   위 스크립트에서 생성한 노트북. v1·v3·v4·v6~v11은 실행 출력 포함
docs/        학습 로그
```

`.py`로 쓰고 `build_nb.py`로 노트북을 만드는 방식을 썼다. 노트북은 실행하기 편하지만 버전 비교·diff는 `.py`가 편해서다.

## 실행

```bash
pip install torch torchvision torchxrayvision pandas pillow scikit-learn
python src/xray_v11_epochs.py
```

각 스크립트 위쪽의 `DATA_DIR`을 `train/`, `test/`, `train.csv`, `test.csv`가 있는 폴더로 바꾸면 된다.
학습된 가중치(`.pt`)는 용량 때문에 포함하지 않았다 — 위 스크립트로 재생성된다.

## 한계

- 검증 정확도(0.960)와 리더보드(0.947)의 간극이 아직 남아 있다. 현재 기수 1위는 0.955다
- v10 단독 모델은 제출하지 않아, 0.9471 중 에포크를 늘린 몫이 얼마인지는 분리하지 못했다
- v1~v9의 제출은 폐렴 판정 기준(0.99)이나 판정 비율(약 58%)을 리더보드를 보며 정했다. 일반화된 선택이 아니다. v10부터는 기준 0.5를 그대로 쓴다
- 환자 ID가 없어 **연속된 10장을 한 환자 묶음으로 가정**했다. 파일 번호가 환자 순서라는 관찰에 근거한 근사다
- test 데이터는 학습·통계에 쓰지 않았다(pseudo-label, AdaBN 미사용). 점수를 더 올릴 수 있는 방법이지만 대회 취지에 맞지 않다고 판단했다
- 띠 단서는 train의 통계로 찾았고, test에서도 그렇다는 것은 비율 분포로 추정한 것이다
